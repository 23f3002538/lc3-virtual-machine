# LC-3 Virtual Machine

A 16-bit [LC-3](https://en.wikipedia.org/wiki/Little_Computer_3) emulator in C for Windows, following [Write your Own Virtual Machine](https://www.jmeiners.com/lc3-vm/), plus architecture analysis tools aimed at systems / GPU-adjacent interview themes (profiling, caches, branches, pipelines, verification).

## Core VM

- 65,536 × 16-bit memory (programs load at `0x3000`)
- Registers: R0–R7, PC, COND (N/Z/P)
- All 16 opcodes (RTI/RES abort)
- Addressing: immediate, register, PC-relative, indirect, base+offset
- Fetch–decode–execute loop
- Traps: GETC, OUT, PUTS, IN, PUTSP, HALT
- Memory-mapped keyboard (KBSR / KBDR)
- `.obj` loading with big-endian byte swap
- Unbuffered console input + Ctrl+C cleanup

## Run demos

```powershell
.\lc3-vm.exe roms\2048.obj
.\lc3-vm.exe roms\rogue.obj
.\lc3-vm.exe roms\halt.obj
```

Ctrl+C restores the console and still prints any enabled analysis reports.

## Analysis tools

| Flag | What it does |
|------|----------------|
| `--trace` | Per-instruction PC, hex, mnemonic, regs, flags |
| `--stats` | Opcode mix, loads / stores / branches |
| `--hotspot` | Top most-executed PCs (where time goes) |
| `--cache` | Direct-mapped cache hit/miss/rate |
| `--cache-lines N` | Cache lines (default 64) |
| `--block-size N` | Words per line (default 4) |
| `--bpred` | 2-bit branch predictor accuracy |
| `--pipeline` | 5-stage CPI with load-use + control hazards |
| `--heatmap` | Writes `heatmap.txt` + `heatmap.html` |
| `--fuzz N` | Differential test N random instructions |
| `--analyze` | Enables stats+hotspot+cache+bpred+pipeline+heatmap |

### Examples

```powershell
# Tiny ROM — full analysis dump
.\lc3-vm.exe --analyze roms\halt.obj

# Play 2048, Ctrl+C for profiles / heatmap files
.\lc3-vm.exe --analyze roms\2048.obj

# Cache sizing experiment
.\lc3-vm.exe --cache --cache-lines 128 --block-size 8 roms\2048.obj

# Verification (no ROM needed)
.\lc3-vm.exe --fuzz 5000

# Instruction trace
.\lc3-vm.exe --trace --stats roms\halt.obj
```

### Memory heatmap

After `--heatmap` or `--analyze`, open:

- `heatmap.txt` — ASCII art
- `heatmap.html` — color grid in a browser

Each cell covers 16 memory addresses; intensity = reads + writes.

## Why these extras map to NVIDIA-style topics

1. **Hot-spot profiler** — find where a workload spends cycles  
2. **Cache simulator** — memory systems / locality  
3. **Branch predictor** — classic CPU microarchitecture  
4. **Pipeline CPI** — hazards and throughput  
5. **Differential fuzzing** — verification mindset  
6. **Heatmap** — visual memory-behavior evidence for a README / write-up
